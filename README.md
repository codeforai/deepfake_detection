# AI Voice Detection API

A REST API that tells whether a voice recording is **AI-generated or human**. It supports Tamil, English, Hindi, Malayalam and Telugu.

Send a Base64-encoded MP3 and get back a classification, a confidence score and a short explanation. The service runs as a Docker container on Render, with health checks, API-key authentication and memory tuning for a 512 MB instance.

**Live:** `https://<your-service>.onrender.com` · **Interactive docs:** `https://<your-service>.onrender.com/docs`

> Hosted on Render's free tier, which sleeps when idle. The first request after a quiet period can take up to a minute while the container starts.

## Background

Built for the **GUVI Hackathon** (February 2026), Problem Statement 1: *AI-Generated Voice Detection*.

AI voice generators can now produce speech that is hard to tell apart from a real person. The task was to build and deploy a secure REST API that:

- accepts one MP3 voice clip per request, sent as Base64
- supports five languages: Tamil, English, Hindi, Malayalam and Telugu
- returns `AI_GENERATED` or `HUMAN`, with a confidence score and a short explanation, in a fixed JSON format
- rejects any request without a valid API key in the `x-api-key` header

Submissions were scored on detection accuracy, consistency across the five languages, the request and response format, API reliability and response time, and explanation quality. Hard-coded results were not allowed, and external detection APIs could be restricted.

## How it works

```
POST /api/voice-detection
        │
        ├─ 1. Check x-api-key header                → 401 if invalid
        ├─ 2. Validate language and audio format    → 400 if unsupported
        ├─ 3. Decode Base64 → MP3 bytes (in memory, nothing written to disk)
        ├─ 4. Decode audio at 16 kHz, first 10 seconds
        ├─ 5. Extract 40 cepstral coefficients × 312 frames
        ├─ 6. Normalize with the training-set mean and std
        ├─ 7. CNN → score between 0 and 1
        └─ 8. score ≥ 0.5 → AI_GENERATED, otherwise HUMAN
```

The model is loaded once at startup and warmed up with a dummy input, so the first real request doesn't pay that cost.

## API reference

### `POST /api/voice-detection`

**Headers**

| Header | Value |
|---|---|
| `Content-Type` | `application/json` |
| `x-api-key` | Your API key |

**Body**

| Field | Type | Description |
|---|---|---|
| `language` | string | One of `Tamil`, `English`, `Hindi`, `Malayalam`, `Telugu` |
| `audioFormat` | string | `mp3` |
| `audioBase64` | string | Base64-encoded MP3 file |

**Example**

```bash
B64=$(base64 -w0 tests/samples/spoof/Telugu_Voice_AI_GENERATED.mp3)   # macOS: base64 -i <file>

curl -X POST https://<your-service>.onrender.com/api/voice-detection \
  -H "Content-Type: application/json" \
  -H "x-api-key: $API_KEY" \
  -d "{\"language\": \"Telugu\", \"audioFormat\": \"mp3\", \"audioBase64\": \"$B64\"}"
```

**Success (200)**

```json
{
  "status": "success",
  "language": "Telugu",
  "classification": "AI_GENERATED",
  "confidenceScore": 0.99,
  "explanation": "Strong indicators of synthetic speech: unnatural pitch consistency, robotic intonation patterns, and artificial spectral characteristics detected"
}
```

| Field | Meaning |
|---|---|
| `classification` | `AI_GENERATED` or `HUMAN` |
| `confidenceScore` | Confidence in the returned class, 0.5–1.0 (the score, or 1 − score for `HUMAN`) |
| `explanation` | Short text chosen from the confidence level |

**Errors**

| Status | When |
|---|---|
| `401` | Missing or wrong `x-api-key` |
| `400` | Unsupported language, non-MP3 format, invalid Base64, or data that can't be decoded as audio |
| `422` | Required field missing from the body |
| `500` | Unexpected server error |
| `503` | More than 5 requests in progress at once (see [Deployment](#deployment)) |

Errors use this shape (except `422`, which uses FastAPI's standard validation format):

```json
{ "status": "error", "message": "Invalid API key or malformed request" }
```

### `GET /health`

Used by Render's health check. Returns `200` with:

```json
{ "status": "healthy", "model_loaded": true, "model_type": "keras3" }
```

### `GET /docs`

Interactive API documentation generated by FastAPI. You can send test requests from the browser.

## Running locally

TensorFlow is a large install, so the first build takes a few minutes.

**With Docker**

```bash
docker build -t voice-detection .
docker run -p 8000:8000 -e API_KEY=choose_a_secret_key voice-detection
```

**Without Docker** (Python 3.10)

```bash
pip install -r requirements.txt
export API_KEY=choose_a_secret_key
python app.py
```

The API is then at `http://localhost:8000`, and the docs at `http://localhost:8000/docs`.

## Configuration

All settings come from environment variables. No secrets are stored in the repository.

| Variable | Required | Default | Purpose |
|---|---|---|---|
| `API_KEY` | Yes | — | Key that clients must send in `x-api-key`. The service refuses to start without it. |
| `PORT` | No | `8000` | Port to listen on. Render sets this automatically. |
| `MODEL_BACKEND` | No | `keras3` | Which model to load: `keras3` (general, deployed), `keras` (TTS), `keras2` (ElevenLabs), `tflite_int8`. Leave unset in production. |

## Deployment

The service is deployed on Render from `render.yaml` (Render "Blueprint"):

- **Docker runtime.** The image is built from the `Dockerfile` on every push to `main`.
- **Health check** on `/health`. A new deploy only receives traffic once it passes the check; if it never does, Render cancels the deploy and keeps the previous version running. If a running instance fails the check for 15 seconds Render stops routing traffic to it, and after 60 seconds it restarts the instance.
- **API key.** Render generates `API_KEY` as a secret on first deploy. Find it in the service's **Environment** tab.

To deploy your own copy: in Render, choose **New → Blueprint**, connect this repository and apply.

### Fitting in 512 MB

The free instance has 512 MB of RAM, and TensorFlow alone uses a large share of it. The container is tuned to stay within that:

| Setting | Where | Why |
|---|---|---|
| `tensorflow-cpu` | `requirements.txt` | Smaller install and image than the full GPU build |
| One Uvicorn worker | `Dockerfile` | Each worker loads its own copy of the model |
| `--limit-concurrency 5` | `Dockerfile` | Caps in-flight requests so memory can't spike; excess requests get `503` instead of crashing the container |
| 2 TensorFlow threads | `app.py` | Stops TensorFlow from starting a thread per host CPU core, which wastes CPU and memory on a small instance |
| `MALLOC_ARENA_MAX=2` | `Dockerfile` | Reduces memory fragmentation from glibc's per-thread allocators |
| Audio decoded in memory | `app.py` | No temporary files on disk |

## Testing and benchmarks

**Tests** load the real model and use the sample clips in `tests/samples/` (2 human, 3 AI-generated). They cover the health check, authentication (including refusing to start without `API_KEY`), input validation, the response format for every clip, and repeatable results.

```bash
pip install -r requirements-dev.txt
pytest -v tests/
```

**CI.** GitHub Actions (`.github/workflows/ci.yml`) runs on every push to `main` and every pull request:

1. Runs the test suite.
2. Benchmarks the deployed model on the sample clips and fails the build if accuracy drops below 80% or p95 inference time rises above 250 ms. The results are saved with each run.
3. Builds the Docker image, starts the container, waits for `/health`, and checks that a request without a key gets `401` and a request with a key is classified.

**Benchmarks** measure accuracy and latency (average and p95) on a folder of labelled clips:

```bash
python benchmarks/benchmark.py                                  # deployed model, sample clips
python benchmarks/benchmark.py --models general tts elevenlabs  # compare models
python benchmarks/benchmark.py --ensemble general tts           # ensemble of two models
python benchmarks/benchmark.py --data /path/to/clips            # folder with real/ and spoof/
python benchmarks/benchmark.py --min-accuracy 80 --max-latency-ms 50   # exits 1 if a target is missed
```

Results are saved as JSON in `benchmarks/results/`.

## Model

| | |
|---|---|
| Architecture | CNN: 4 convolution blocks (32 → 256 filters) with batch norm and dropout, then 2 dense layers and a sigmoid output |
| Input | 40 cepstral coefficients × 312 frames (10 s of 16 kHz audio) |
| Training data | ~136,000 clips, balanced between human and AI-generated |
| Test accuracy | 99.99% on a held-out split of 27,200 clips |
| Inference time | ~4 ms per clip on CPU (model only; excludes decoding and feature extraction) |
| Size | 1.7 MB |

Training: `notebooks/lfcc-cnn-model-oldest.ipynb` (runs on Kaggle with the dataset attached).

### Other models evaluated

These are kept in `model/` for comparison and are not used by the service:

| Model | Notes |
|---|---|
| `best_model_tts.h5` | Same CNN, trained on TTS-generated speech |
| `best_model_elevenlabs.h5` | Same CNN, trained on ElevenLabs speech |
| `model_int8.tflite` | ElevenLabs CNN quantized to 8-bit TFLite, about 4× smaller |
| `model_xgboost*.json`, `.ubj` | XGBoost on 365 summary statistics of the same features (notebook: `notebooks/xg-boost.ipynb`) |

`experiments/convert_models.py` produces the TFLite versions. INT8 calibration currently uses random inputs rather than real audio features, so expect some accuracy loss from the quantized model.

## Limitations

- **Accuracy on new data is lower than the test figure.** The train/test split was made clip by clip, so the same speakers and sentences appear on both sides. The 99.99% measures performance on data like the training set. On the 5 independent clips in `tests/samples/`, the model classifies 4 correctly (it misclassifies the Tamil human clip). Splitting by speaker would give a more realistic estimate.
- **The `language` field is validated but not used by the model.** One model handles all five languages.
- **Only the first 10 seconds** of each clip are analyzed. Shorter clips are zero-padded.
- **Explanations are rule-based.** They are chosen from the confidence level and don't come from analyzing specific features of the audio.
- **One shared API key** and no rate limiting beyond the concurrency cap.
- **Cold starts** of up to a minute on the free tier.
